# Local Development & Testing Scripts

Данная директория содержит служебные скрипты для запуска локального окружения, интеграционного и нагрузочного тестирования подсистемы анализа МРТ (микросервисы, очередь Kafka/Redpanda, база данных PostgreSQL, S3/MinIO, WSL2/GPU инференс `nnU-Net` и Next.js веб-приложение).

---

## 1. Запуск локального окружения

### `start-local-env.bat` / `start-local-env.ps1`
**Назначение:** Главный оркестратор для быстрого поднятия всей системы разработки в один клик под Windows / WSL2.

**Что делает:**
1. Запускает бэкенд в Docker (`postgres`, `minio-s3`, `redpanda-0`, `redpanda-console`, `auth_service`, `exam_service`, `med_service`, `composition_api`).
2. Ожидает готовности базы данных (`pg_isready`), инициализирует бакеты в MinIO (`mri`, `kt-b`) и сервисный аккаунт S3.
3. Автоматически запускает сервис машинного обучения (`ml_service`) внутри дистрибутива **WSL2 Ubuntu** с использованием выделенного виртуального окружения Python и GPU (NVIDIA CUDA).
4. Запускает локальный веб-сервер фронтенда (`Next.js MRI App`) на порту `3005`.
5. По нажатию `Q`, `Ctrl+C` или `Ctrl+X` корректно и без зависания завершает все зависимые процессы в Windows и WSL2.

**Использование:**
```cmd
.\scripts\start-local-env.bat
```
или из корня:
```cmd
.\start-local.bat
```

## 2. Скрипты тестирования и валидации

### `test_mri_pipeline.py` (или `e2e_mri_test.py`)
**Назначение:** Сквозное (E2E) тестирование пайплайна обработки МРТ-исследования через REST API Gateway.

**Что делает:**
1. Регистрирует уникального тестового врача через `POST /api/v1/reg/doctor`.
2. Авторизуется и получает JWT токен через `POST /api/v1/login`.
3. Загружает тестовый многостраничный снимок `_test_data/patient_T1.tif` через `POST /api/v1/mri`.
4. Опрашивает базу данных `examdb` до момента, пока нейросеть `nnU-Net` в WSL2 не завершит сегментацию и сохранение полигонов в таблицу `segment`.
5. Выводит в консоль сводку по найденным узлам и контурам.

**Использование:**
```bash
python scripts/test_mri_pipeline.py
```

---

### `test_frontend_integration.py`
**Назначение:** Валидация работы Next.js API Proxy (`http://localhost:3005/api/v1`).

**Что делает:**
* Проверяет проксирование запросов авторизации, загрузки `.tif` и скачивания нарезанных PNG-срезов через веб-сервер Next.js на шлюз `composition_api`.
* Автоматически определяет сетевой шлюз (gateway IP) при вызове изнутри WSL2.

**Использование:**
```bash
python scripts/test_frontend_integration.py
```

---

### `verify_mask_overlay.py`
**Назначение:** Проверка точности геометрического совмещения сгенерированных ИИ-масок со срезами МРТ.

**Что делает:**
1. Подключается к серверу, скачивает 16-битные PNG-срезы последнего обработанного исследования и координаты полигонов `contor`.
2. Нормализует яркость 16-битных срезов до $0..255$.
3. Накладывает векторные полигоны масок прямо на пиксели снимка.
4. Генерирует контрольное изображение со срезами (сетку сравнения) для визуальной проверки точности локализации аденомы гипофиза.

**Использование:**
```bash
python scripts/verify_mask_overlay.py
```

---

### `compare_t1_t2_channels.py`
**Назначение:** Численное исследование влияния различных комбинаций входных каналов на точность модели `nnU-Net`.

**Что делает:**
* Прогоняет инференс на реальных весах модели с вычислением метрики **Dice Score** и объема сегментации относительно эталонной маски (`patient_T1_MASK.tif`):
  * T1 в обоих каналах (`T1 + T1`)
  * Только T1 (`T1 + 0`)
  * T1 поданный только во 2-й канал (`0 + T1`)
  * T1 + синтетический T2 (инвертированный T1)
* Формирует итоговую сравнительную таблицу метрик.

**Использование:**
Запуск в среде WSL2 с активированным GPU:
```bash
wsl -d Ubuntu -- /home/doge/.venvs/ml_service/bin/python3 scripts/compare_t1_t2_channels.py
```
